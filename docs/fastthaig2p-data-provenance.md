# FastThaiG2P browser data provenance and redistribution review

**Scope:** the exact FastThaiG2P source pin used by the browser/WASM port:
`4e82a291b4cf2876326744c6580121e9986ad354`.

## What the upstream source actually contains

The upstream `data/README.md` describes:
- `dict.txt`: a 62k-word runtime word list used by tokenization and IPA lookup;
- `ipa.json`: a flat runtime lookup merged from Wiktionary and generated IPA;
- `ipa_metadata.json`: per-word source metadata, used for auditing;
- fallback files described as vendored from TLTK.

The upstream `scripts/merge_ipa.py` explicitly labels IPA entries `generated`, `wiktionary`, or `manual`, with precedence manual > Wiktionary > generated. The generated source is described in upstream documentation as roughly 49k entries produced by Claude Opus 4.6. The runtime wheel includes the merged `ipa.json` and `dict.txt`, but not the source-separated audit metadata.

## Build-time source filtering now implemented

`scripts/prepare_fastthaig2p_browser_source.py` prepares a dedicated browser wheel from the pinned source checkout:
1. Reads `ipa_metadata.json`, `ipa.json` and `dict.txt`.
2. Retains only entries explicitly labelled `wiktionary` or `manual`.
3. Excludes `generated` and any unknown/missing source labels.
4. Requires the IPA string in the metadata and runtime map to match exactly and be slash-delimited.
5. Reduces the tokenizer wordlist to exactly the retained IPA keys while preserving upstream word order.
6. Writes a machine-readable source-count report.

The upstream TLTK-derived OOV fallback remains enabled; it is not replaced by an invented Ukrainian or JavaScript fallback. The browser build and parity workflow now use this filtered wheel rather than the unfiltered upstream wheel.

The CI gate requires a non-empty Wiktionary subset and a non-empty generated subset before filtering. It also runs focused tests for source selection, exact IPA metadata agreement, and malformed IPA rejection. Exact retained/excluded counts are emitted by the workflow and must be copied into the final evidence register only after the run passes.

## Source and license evidence

### Wiktionary-derived entries

- FastThaiG2P source documentation identifies `wiktionary_ipa.json` as a 13k-entry extraction from kaikki.org and describes the merge into `ipa.json`.
- Kaikki's Thai Wiktionary data page says its extracted data is made available under the same licenses as Wiktionary: CC BY-SA and GFDL.
- Wiktionary's copyright page identifies CC BY-SA 4.0 and GFDL as the dual licenses for original entry text.

Sources:
- https://github.com/awslabs/FastThaiG2P/blob/4e82a291b4cf2876326744c6580121e9986ad354/data/README.md
- https://github.com/awslabs/FastThaiG2P/blob/4e82a291b4cf2876326744c6580121e9986ad354/scripts/merge_ipa.py
- https://kaikki.org/thwiktionary/index.html
- https://en.wiktionary.org/wiki/Wiktionary:Copyrights

The filtered dictionary is a transformed subset of Wiktionary-derived pronunciation records. The browser distribution must identify Wiktionary contributors and kaikki.org, link to the source, disclose the filtering/modification, make the filtered dataset available under the applicable share-alike terms, and provide the relevant license texts/links. This source filtering is a provenance improvement, not a legal certification.

### Manual overrides

The pinned upstream source labels these entries `manual` and places them in the FastThaiG2P repository. They are retained with the upstream software package and its Apache-2.0 license/NOTICE. No separate external source is identified for these manual overrides in the pinned repository.

### Model-generated entries

The upstream repository says `generated_ipa.json` contains approximately 49k IPA entries generated by Claude Opus 4.6. Their individual provenance and redistribution license are not recorded in the runtime package. They are now excluded from the browser wheel. The unfiltered upstream wheel must not be staged for public Pages deployment.

### TLTK-derived fallback

The pinned FastThaiG2P README and data README say the OOV fallback is vendored from TLTK. Several fallback asset Git blob hashes match files in the public `attapol/tltk` repository, supporting the stated origin.

The PyPI TLTK project page states that the package license changed to BSD-3-Clause from version 1.2.2, and the PyPI 1.3.8 release page identifies BSD-3-Clause. The TLTK GitHub repository also currently contains a root `LICENSE` file for LGPL-3.0 and a separate `LICENSE.txt` for BSD-3-Clause; its historical `PKG-INFO` identifies an older GPLv3 version. FastThaiG2P does not record the exact TLTK release/commit used for every vendored fallback file.

Sources:
- https://pypi.org/project/tltk/1.3.8/
- https://pypi.org/project/tltk/
- https://github.com/attapol/tltk
- https://github.com/awslabs/FastThaiG2P/blob/4e82a291b4cf2876326744c6580121e9986ad354/data/README.md

**Remaining evidence requirement:** establish the exact TLTK source release/commit for the vendored code and data and reconcile file-level license notices. The current evidence supports BSD-3-Clause for the published TLTK package release, but does not by itself identify the precise source release copied into FastThaiG2P. Keep the public redistribution flag false until this mapping and notices are reviewed.

### Other runtime dependencies

- FastThaiG2P software: Apache-2.0, pinned upstream commit above.
- PyThaiNLP 5.4.0 software: Apache-2.0. The browser wheel retains only Python source plus `words_th.txt`, `stopwords_th.txt` and `corpus_license.md`; both retained corpus lists are CC0-1.0.
- Pyodide 0.29.5: MPL-2.0.
- tzdata 2026.6: Apache-2.0.
- This project: MIT.

The Pages bundle must carry the corresponding license and NOTICE texts, the filtered data attribution, and an exact file/hash manifest.
